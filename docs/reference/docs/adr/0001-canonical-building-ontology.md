# Structure, Space, Asset en Point als canoniek gebouwmodel

ONE.OS gebruikt strikt `Site → Structure → Space → Asset → Point` als canoniek containmentmodel, omdat dit naast gebouwen en verdiepingen ook daken, gevels, terreinen, parkings, gebruiksruimtes en samengestelde gebouwfuncties kan modelleren. Structures mogen recursief andere Structures bevatten; iedere Space behoort aan precies één Structure, ieder Asset aan precies één Space en ieder Point aan precies één Asset. Ontbrekende bronplaatsing gebruikt zichtbare synthetische `Unassigned`-containers in plaats van niveaus over te slaan. Building en Floor blijven Structure-types, Zone blijft een Space-type en Equipment blijft een Asset-type; een PhysicalDevice staat buiten containment omdat één fysiek apparaat meerdere Assets kan realiseren.
